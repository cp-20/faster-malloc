# Round 8 measurement reproduction

Run from the repository root at 337d7d5; allocator sources/defaults are unchanged.
`measure.py` writes raw samples (including the excluded rep-0 warmups),
`matrix.py` writes every individual cell result, and `summarize.py` reports
medians, sample variance/SD, CV and ranges (null CV for all-zero error counts). Do not run correctness or compilation jobs
alongside timings. These drivers intentionally retain the paths used in the
cloud session, rather than changing global installations.

Prerequisites for this recorded run:

* `make -j4`; GCC 14.2, Debian 13, jq 1.7 (system binary).
* Distro `.deb` files extracted with `dpkg-deb -x` under `work/tools`:
  lua5.4, ruby3.3, libruby3.3, ruby-json, rubygems-integration, nginx,
  nginx-common, postgresql-17, postgresql-client-17, libmimalloc3,
  libtcmalloc-minimal4t64, time, liburing2, libnuma1, libyaml-0-2, libgmp10.
  `work/bin/nginx` and `work/bin/ruby` symlink their extracted binaries.
  jemalloc is the system `/lib/x86_64-linux-gnu/libjemalloc.so.2`.
* `work/big.json` is the seeded 200k-record fixture generated by the Python
  block in `bench/apps/prep.sh` (no need for the SQLite/git fixture downloads).
* Build the historical control with exactly the current O3 flags:

```sh
mkdir -p work/round6
 git archive f6d5875 src | tar -x -C work/round6
cc -O3 -g -fPIC -fno-plt -Wall -Wextra -Wno-unused-parameter \
  -Iwork/round6/src -shared -o work/round6/libfastmalloc2.so \
  work/round6/src/fm_static.c
cc -O2 -g -Wall -Wextra -pthread -o work/ownership bench/ownership.c

python3 bench/round8/matrix.py

python3 bench/round8/summarize.py > bench/results/round8/summary.json
```

The historical control has known ownership races (ADR 0035). It is a
measurement control, never a candidate for deployment. No locks were removed
from current code. `ownership.c` checks every transfer's endpoints/counts;
its 128 requested sizes map to 64 distinct allocator classes.
`mt` local is eight threads; `mt` cross is **two**, regardless of its last arg.

Matrix: five complete rounds, rotated and reversed allocator orders, one run
per cell invocation (`REPS=PGREPS=1` bypasses the legacy min/max reducer).
Each pgbench cell creates a fresh scale-5 database. nginx uses 2 workers,
20 connections, 10 s; pgbench uses 4 clients / 2 jobs, 15 s. No shortened
load intervals. Ruby's cell uses GNU time's 0.01 s resolution. The raw matrix
retains failure status/stderr and must contain no FAIL/MISSING or checksum
mismatch. PostgreSQL is v17 here, not round 6's v16: compare within this round.
Summed server RSS double-counts shared mappings; it is not PSS.

For separate, untimed realloc-path counts:

```sh
cc -O2 -shared -fPIC -o work/realloccount.so bench/realloccount.c -ldl
# Preload the counter first, then the allocator, and use the same workload
# commands/environment as measure.py. Never time this instrumented process.
LD_PRELOAD="$PWD/work/realloccount.so:$PWD/libfastmalloc2.so" \
  work/tools/usr/bin/lua5.4 bench/apps/workloads/churn.lua
```

`large_growth` means a non-NULL realloc request >32 KiB and greater than
current usable size, where the wider cache policy might run. Counts include
startup. `realloccount.c` uses dlsym and is diagnostic-only, not production code.
The initial execution script's jq expected literal was corrected from 66473
to the fixture's actual 66395 on the first warmup; all saved outputs must be
66395. The committed driver strictly checks that value on every run.

The realloc set includes Python 3.12.14's existing `churn.py` as a realloc-heavy
application. jq is retained as a negative control: instrumentation found zero
non-NULL realloc calls on this build, so it does **not** count as one of the two
additional realloc-heavy apps. Python and Ruby supply that coverage. Python's
pymalloc still serves small objects internally; count/interpret only the libc
realloc subset rather than claim every Python allocation reaches this policy.
The Python pairs were collected after this reachability check, before the
resumed matrix; no other measurement job ran alongside them.

Attempts are retained, including incomplete matrix output. The first nginx/v2
RSS read raced an in-place sampler write; atomic rename fixes publication.
Editing an active pgbench shell script then caused a parse error after its
workload, and editing the queued diagnostic script interrupted that driver too.
The matrix stopped on the failure. All active script edits were then stopped;
`matrix.py` resumed with frozen scripts, retaining both invalid attempts and
rerunning those cells. `matrix-exclusions.json` identifies excluded raw row
indices/reasons. Exclusion is for missing metadata/nonzero harness status,
never an outlier timing. Run on a fresh output directory for a fresh experiment;
the matrix driver otherwise resumes completed cells. Diagnostic counts are
untimed, and interrupted diagnostics are preserved separately.

`lockprice.c` is a separate current-v2 diagnostic build using GNU ld's
`--wrap=pthread_mutex_lock`. Match its reported mutex offsets to the captured
`nm` symbols. Its acquisition durations include mutex wait/entry, two clock
reads and instrumentation effects, and overlap across threads. They are not
held time, pure wait time, or numbers to subtract from uninstrumented wall time.

GNU time was also absent at the first Ruby matrix attempt; that FAIL is
retained, excluded for missing tooling, and rerun with extracted `time` via
`TIME_BIN`. The matrix driver supports resumption only after investigating a
failure; do not treat rerunning a failed application as a correctness pass.
The exact failed output/reason remains in the raw records and exclusions.
