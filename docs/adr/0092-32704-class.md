# 0092 — A 32704-byte class so payload + header fits eight pages

Proposed 2026-11-25.

## Context

Round 38 measured the 32 KiB class at **38,848 bytes of RSS per live
block against glibc's 34,752** (+4,096, one page, +11.8%).  The cause is
the span arithmetic: for `bs = 32768`,

    nblocks = (65536 - 64) / 32768 = 1

so the block lives alone in a 64 KiB span at offset 64, and a 32768-byte
payload touches pages 0..8 (nine pages) instead of eight.

The fix that needs no new lookup is to make the *class* small enough that
payload plus header is exactly eight pages:

    payload + 64 = 32768  =>  payload = 32704
    nblocks = (65536 - 64) / 32704 = 2

Two blocks per span, each occupying exactly eight pages including its own
header -- zero spill, and the span header page is shared by both blocks.

## Decision

Insert a 32704-byte class into the ladder before the existing 32768 one.
Requests up to 32704 round to it; requests in 32705..32768 keep the old
class and its one-block span.  The fast paths do not change: the class
lookup table is regenerated, the dispatch arithmetic is identical.

## Evidence

Local, interleaved:

| case | main | 32704 class |
|---|---:|---:|
| gcc `-O1 -c sqlite3.c` | 370.2-370.5 MB | **351.8 MB** |
| lua churn | 16.4-16.6 MB | **14.8-15.0 MB** |
| sqlite speedtest1 | 11.5-11.6 MB | **10.9-11.1 MB** |
| git rev-list | 23.9-24.0 MB | 23.9-24.0 MB |

Time is unchanged everywhere.  A paired 11-rep run of the exact legacy
gcc workload (interleaved) gives RSS 370,196 -> 351,772 KiB
(**-18,416 KiB, -18.0 MiB**) at a paired time ratio of **1.0000**.

Instruction count (callgrind): churn 64 1.00079, churn 1024 1.00148,
mixed 1.00058, cross 1.00086.

`test_basic`, `stress`, `rtest` pass.  11-rep exp-bench: **micro 1.0000 /
worst 1.0000**, real paired 0.9939, the seven fixtures' RSS flat (they
carry no 32 KiB traffic).  The first CI run failed the JIT `cross` gate
once; a re-run passed it and the same test passes 10/10 locally, so it
was a flake.  The legacy matrix, where gcc/lua/sqlite put 32 KiB payloads
through this class, is the decisive one.

## Risks

* Requests in 32705..32768 still pay the old spill; they are the only
  band that does not benefit.
* The ladder grows by one class (145 -> 146), which shifts no fast-path
  arithmetic but changes the TLS array sizes.
