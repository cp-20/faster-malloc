# Round 10 — 2026-11-13

## v1 alignment error-path audit (ADR 0047)

Branch: `round10/v1-memalign`; base: `f90550c`.

Audited v1 `posix_memalign`, `aligned_alloc`, `memalign`, `valloc`, `pvalloc`
and their shared allocation helper. Removed the invalid-alignment output
store from `posix_memalign` and rejected zero alignment, matching ADR 0044.
ENOMEM already preserves the output. Shared helper validation now rejects
zero/non-power-of-two alignments with NULL/EINVAL for `aligned_alloc` and
`memalign`. Page-aligned APIs have fixed valid alignment and no output-pointer
argument; no corresponding defect was found. Allocation policy is unchanged.

Added `bench/v1align` to make/clean and explicitly to `bench/round7.sh` under
v1. Volatile indirect calls check invalid alignment, unchanged sentinels on
EINVAL and ENOMEM, failure returns for every entry point, and valid aligned
allocation/free. Running the probe against the original v1 DSO fails on the
alignment-3 sentinel assertion; fixed v1 passes.

Validation: `make`; full `bash bench/round7.sh`; the 12 FM_DEBUG stress cases
from `bench/round9/verify.sh` (locked/epoch × static/JIT × three repetitions,
with idle release, cache search and aggressive purge enabled); and the v1
alignment probe against an FM_DEBUG build. All passed. No performance
measurements or allocation-size/page-rounding policy changes are included.

### 日本語まとめ

v1 のアラインメント関連 API を監査した。`posix_memalign` は失敗時に
出力ポインタを変更せず、アラインメント 0 を EINVAL として拒否する。
`aligned_alloc` と `memalign` も共有ヘルパーで 0 と 2 の累乗でない値を
拒否する。`valloc` と `pvalloc` に同種の不具合はなかった。
volatile な関数ポインタを使う v1 専用の回帰テストを通常のバッテリーに
追加し、修正前の失敗と修正後の成功を確認した。全バッテリーと
FM_DEBUG 検証は成功。割り当て方針は変更していない。
