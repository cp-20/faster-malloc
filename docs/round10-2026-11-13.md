# Round 10 — 2026-11-13

## v1 alignment error-path audit (ADR 0047)

Branch: `round10/v1-memalign`; base: `f90550c`.

Audited v1 `posix_memalign`, `aligned_alloc`, `memalign`, `valloc`, `pvalloc`
and their shared allocation helper. Removed the invalid-alignment output
store from `posix_memalign` and rejected zero alignment, matching ADR 0044.
ENOMEM already preserves the output. Shared helper validation now rejects
zero/non-power-of-two alignments with NULL/EINVAL for `aligned_alloc` and
`memalign`. Page-aligned APIs have fixed valid alignment and no output-pointer
argument; no corresponding defect was found. Allocation policy is unchanged.

Added `bench/v1align` to make/clean and explicitly to `bench/round7.sh` under
v1. Volatile indirect calls check invalid alignment, unchanged sentinels on
EINVAL and ENOMEM, failure returns for every entry point, and valid aligned
allocation/free. Running the probe against the original v1 DSO fails on the
alignment-3 sentinel assertion; fixed v1 passes.

Validation: `make`; full `bash bench/round7.sh`; the 12 FM_DEBUG stress cases
from `bench/round9/verify.sh` (locked/epoch × static/JIT × three repetitions,
with idle release, cache search and aggressive purge enabled); and the v1
alignment probe against an FM_DEBUG build. All passed. No performance
measurements or allocation-size/page-rounding policy changes are included.

## Ownership-lock cost (`round10/lock-cost`)

Based on main f90550c. This section and ADRs 0048–0049 belong only to the
ownership-lock task. No epoch redesign: ADR 0041 remains rejected.

### Method and results

Same-session f90550c control compiled with GCC 14.2/O3; its .text was checked
against a fresh git-object build and matched exactly. Two separate series,
each one warmup pair plus five measured alternating pairs per case. The
second series remeasured the same baseline rather than pooling earlier
controls. Times bracket subprocess startup/exit using monotonic wall time.
All samples and outputs remain in `bench/results/round10-lock-cost/`, with
CVs and paired counts in summary.json. No slow samples were removed.

Shared Xeon Platinum 8573C host, two-CPU cgroup quota: indicative cloud
measurements, not reference-VM results. No correctness tests overlapped timing.
Two short compilations overlapped the stripe series; none overlapped the
adaptive series. Local is eight threads × 10M operations; cross is two threads
with 10M transfers despite the legacy final `8` argument. Many/census use the
unchanged round-8 harness: four pairs, 200k transfers each, 64 allocator classes;
census adds explicit trims. Every transfer/count assertion passed.

**Attempt 1 — central stripes (ADR 0048): reject default adoption.** Sixteen
class-group central locks, global census lock unchanged; fork quiesces every
stripe. Median gains are modest and ranges overlap; extra machinery is not
justified. Retain a disabled reproduction patch, not active allocator code.

## Short-lived Python and Node RSS

This section owns only the short-lived app work (ADRs 0050–0053), based on
`f90550c`. Adopt **`FM_PROFILE=shortlived`**, which uses balanced span policy and
sets only the per-thread large-cache budget to zero. The existing
`FM_LCACHE_MAX_BYTES` override still wins. Balanced defaults are unchanged.

Measurements use the existing `bench/apps` fixture, workloads and
`run_timed.py`, one invocation per sample, five rotated/interleaved rounds in
the same container. Tables show **median (minimum–maximum)**, RSS in KiB and
time in seconds. This shared cloud container has a two-CPU quota, Python
3.12.14, Node v24.22.1, jemalloc 5.3.0 and mimalloc 2.1.7; ranges describe this
session and do not establish controlled-hardware rankings. All app checksums
match (Python 625726, Node 671898); no failed or slow final sample is dropped.
Lua is excluded per ADR 0031.

`eager` is footprint plus zero requested release age and interval floor/cap
(the two intervals clamp to 1 ms). Footprint is a useful reduction, but zero
cache saves more. Eager ageing does not provide a material extra reduction;
reject that policy and avoid adding pressure-triggered release machinery.
An exit-only drain cannot lower an earlier process high-water mark, and thread
exit already drains large caches, so no additional exit hook is warranted.

The shortlived median peak falls by **12.1% for Python and 10.4% for Node**
relative to balanced v2. It remains **1.1% and 3.4% above same-session glibc**.
Timing ranges overlap; no speed improvement is claimed. Disabling reuse can
cost mmap/munmap work on other large-block workloads; this is an opt-in preset,
not a general replacement for balanced or footprint.

### Where the peak goes

A separate diagnostic build counts live API usable capacity, marks cached large
blocks and tracks small-span live capacity without changing span layout. A parent
pauses the child, reads resident headers and pagemap, and retains the largest
sampled RSS snapshot, three runs per app/profile. These are sampled synchronized
snapshots, not exact decompositions of wait4's historical HWM; instrumentation
and pauses change timing. Individual category medians need not sum to median
total RSS because the peak instant differs across runs.

Usable capacity is **not resident live bytes**: free blocks can share resident
pages with live blocks. Fully free spans include local/central retention and
headers; partially live spans mix live pages, fragmentation and free blocks.
The baseline column counts file-backed mappings, named main stack and kernel
mappings at the same instant. Other anonymous RSS includes Python pymalloc/V8
direct mappings, anonymous thread stacks and allocator metadata; it is neither
all live payload nor all allocator retention. Large aligned headers outside the
64 KiB boundary remain in this residual. Cached-large residency is summed over
threads and can exceed one thread's configured budget. These limits prevent a
false claim that the entire peak is explained by malloc-requested bytes.

The large cache is the movable tens-of-MiB component; removing it leaves a large
runtime-managed residual. Fully free small-span retention is much smaller and
zero-age release does not move this peak appreciably. Further closing the glibc
gap requires a different investigation, rather than assuming the residual is
reclaimable free memory.

harness, the Python launcher inherits LD_PRELOAD; fork/exec HWM can include its
initial inherited pages, especially for minimal Python startup.
