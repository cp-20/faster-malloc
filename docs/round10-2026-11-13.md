# Round 10 — 2026-11-13

## v1 alignment error-path audit (ADR 0047)

Branch: `round10/v1-memalign`; base: `f90550c`.

Audited v1 `posix_memalign`, `aligned_alloc`, `memalign`, `valloc`, `pvalloc`
and their shared allocation helper. Removed the invalid-alignment output
store from `posix_memalign` and rejected zero alignment, matching ADR 0044.
ENOMEM already preserves the output. Shared helper validation now rejects
zero/non-power-of-two alignments with NULL/EINVAL for `aligned_alloc` and
`memalign`. Page-aligned APIs have fixed valid alignment and no output-pointer
argument; no corresponding defect was found. Allocation policy is unchanged.

Added `bench/v1align` to make/clean and explicitly to `bench/round7.sh` under
v1. Volatile indirect calls check invalid alignment, unchanged sentinels on
EINVAL and ENOMEM, failure returns for every entry point, and valid aligned
allocation/free. Running the probe against the original v1 DSO fails on the
alignment-3 sentinel assertion; fixed v1 passes.

Validation: `make`; full `bash bench/round7.sh`; the 12 FM_DEBUG stress cases
from `bench/round9/verify.sh` (locked/epoch × static/JIT × three repetitions,
with idle release, cache search and aggressive purge enabled); and the v1
alignment probe against an FM_DEBUG build. All passed. No performance
measurements or allocation-size/page-rounding policy changes are included.

## Ownership-lock cost (`round10/lock-cost`)

Based on main f90550c. This section and ADRs 0048–0049 belong only to the
ownership-lock task. No epoch redesign: ADR 0041 remains rejected.

### Method and results

Same-session f90550c control compiled with GCC 14.2/O3; its .text was checked
against a fresh git-object build and matched exactly. Two separate series,
each one warmup pair plus five measured alternating pairs per case. The
second series remeasured the same baseline rather than pooling earlier
controls. Times bracket subprocess startup/exit using monotonic wall time.
All samples and outputs remain in `bench/results/round10-lock-cost/`, with
CVs and paired counts in summary.json. No slow samples were removed.

Shared Xeon Platinum 8573C host, two-CPU cgroup quota: indicative cloud
measurements, not reference-VM results. No correctness tests overlapped timing.
Two short compilations overlapped the stripe series; none overlapped the
adaptive series. Local is eight threads × 10M operations; cross is two threads
with 10M transfers despite the legacy final `8` argument. Many/census use the
unchanged round-8 harness: four pairs, 200k transfers each, 64 allocator classes;
census adds explicit trims. Every transfer/count assertion passed.

**Attempt 1 — central stripes (ADR 0048): reject default adoption.** Sixteen
class-group central locks, global census lock unchanged; fork quiesces every
stripe. Median gains are modest and ranges overlap; extra machinery is not
justified. Retain a disabled reproduction patch, not active allocator code.

**Attempt 2 — opportunistic automatic census (ADR 0049): adopt.** A busy
automatic census returns before flushing/detaching/touching span state;
explicit trim still blocks. TLS result counters reset before the attempt.
Every actual census retains global exclusive ownership. Central header
ownership, atomic dead_mark, purge coverage and withheld geometry are unchanged.

Adaptive faster pairs: local 5/5, cross 2/5, many 5/5, census 5/5. The cross
median regression remains visible; no universal speedup is claimed. Automatic
reclamation may wait for a later tick/idle sweep under contention, with no
bounded reclaim latency guarantee. Explicit trim retains blocking semantics.

### Validation and reproduction

Both pre-promotion default and adaptive `make -B -j4` plus full `round7.sh`
batteries passed, including twelve-thread purge/churn, FM_DEBUG static/JIT ×3
per configuration (12 stress runs), all profiles/opt-ins, lifecycle/fork fault
matrix, early-init/TLS exit and the retained epoch test. The focused busy-lock
check passed. The promoted v2 .text exactly matches the measured candidate;
its final ordinary-default full battery also passed (separate transcript). No allocator races
or failed runtime checks were observed; this is not an exhaustive race proof.
Default is now `FM_CENSUS_TRYLOCK=1`; build with `=0` for a blocking control.
No application-matrix or quiet-reference-machine validation was attempted.
Reproduce throughput using
`bash bench/round10/lock-cost.sh` and validation using
`bash bench/round10/lock-cost-verify.sh`. The first focused-test compilation
needed a missing stdio include; corrected before any test executed.
