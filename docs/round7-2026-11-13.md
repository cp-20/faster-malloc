# Round 7 — cache search stays opt-in; purge and timer ownership hardened

*EN summary: Round 7 implements the requested three items in order after
reading round 6 and its cited ADRs. Wider large-cache search for realloc
is available as `FM_REALLOC_CACHE_SEARCH=1`, default off: a pointer-reuse
regression proves the mechanism, but the Lua workload provides no adoption
case. Twelve-thread purge/churn stress and an ownership audit expose races
in shared census state, span metadata and batch-header recycling; slow-path
ownership is now serialized. The idle timer registers fork handlers once,
quiesces censuses before fork, stays disabled in children until exec, and
blocks application signals. The full correctness battery passes under v2
and JIT, with both opt-ins also tested together. All performance and RSS
numbers below are indicative cloud-container measurements, not comparable
to the reference VM; final adoption verdicts are re-measured downstream.*

## 1. Large-cache search on realloc growth (ADR 0034)

`FM_REALLOC_CACHE_SEARCH=1` extends plain large realloc's cache search beyond
the request bucket and its successor, visiting larger buckets in ascending
order, at most eight entries per bucket. Existing capacity-in-mapping reuse
still wins first. The byte budget, actual usable-capacity checks and
unlink/copy/free logic are preserved. Ordinary malloc/calloc and aligned or
small-class realloc keep their allocation policy. The new knob uses the
existing lazy FM_* configuration parser and defaults to 0 in all profiles.

`bench/realloccache.c` caches an 8 MiB mapping, then grows a 128 KiB block
to 256 KiB. The output pointer must equal that cached address only with the
flag enabled; all preserved data and subsequent calloc zeroing are checked.
Both builds pass both settings; calloc must also avoid that distant mapping.

The first rgrow pair, 200 rounds / 2,200 operations:

| build | search off, s | search on, s |
|---|---|---|
| v2 | 0.189635 | 0.197973 |
| JIT | 0.193554 | 0.206199 |

Real workload: existing `bench/apps/workloads/churn.lua`, executed by the
installed `texlua` interpreter. It is not the reference VM's Lua binary.
Three alternating v2 pairs (seconds / peak RSS KiB):

| pair | search off | search on |
|---|---|---|
| 1 | 0.372999 / 26240 | 0.349009 / 26496 |
| 2 | 0.291537 / 26624 | 0.295093 / 26624 |
| 3 | 0.313871 / 26496 | 0.336505 / 26752 |

Checksum **19466078** every time. Median time 0.313871 → 0.336505 s;
median RSS 26496 → 26624 KiB. A syscall-count pair on the hardened build
also offers no mechanism win: mmap 548 → 559, munmap 538 → 550, including
startup. Timing noise and interpreter differences prevent a performance
verdict for the reference VM. The evidence here supports **retaining the
requested opt-in prototype, rejecting default promotion**. A smaller freed
predecessor still cannot serve a larger request; this can reuse larger
already-cached mappings, not erase one-way growth trails by itself.

## 2. Purge under contention (ADR 0035)

The stress harness now runs eight purge workers with four randomized churn
workers. Each purge worker repeats 24 fully touched bursts of 2,048 × 896 B,
frees all but every sixteenth block, trims, refills the same class with live
islands still present, verifies bytes, grows the islands to 1,792 B and
trims again. Other workers concurrently exercise free/realloc/calloc/aligned
allocations and retain local free lists. Page-straddling blocks and live
islands exercise ADR 0030's intersect/start-count proof under contention.

Audit findings and fixes:

- Census scratch counters and the allocation-failure flag were shared across
  threads. They are now thread-local, with results reset even on an empty
  census; automatic cadence consumes these results after the census returns.
- Disjoint detached lists do not imply disjoint spans. Two censuses could
  race on a span's purge/reclaim metadata. A census mutex now gives one
  owner to the whole count/decide/rebuild/purge/publish operation.
- A Treiber pop could read `b->next` while another pop or census recycled
  that header through a thread-local batch pool. Push/pop/detach now have
  short central-stack ownership, ending the stale-reader/ABA hazard.
  `dead_mark`, shared with refill, is atomic.

These are code-audit races, not reproduced corruption: ten pre-fix debug
stress runs passed. The start-count rule itself needed no change. The
ownership fix supersedes the old lock-free central implementation; hot
thread-local allocation/free remain lockless. Fork handlers in item 3 use
the same census-then-central lock order.

The harness had its own hidden problems: a shared RNG raced, and successful
iterations never released slot reservations. Once slots filled, workers
mostly skipped instead of continuing churn. Both are fixed; failed realloc
also releases its reservation, final live slots are checked, and calloc's
entire allocation is verified. The final battery uses this corrected harness.

A traced final stress run issued **9,287 MADV_DONTNEED calls**, with no failed
madvise lines. Purge is actually exercised; this is not merely a thread-count
or whole-span-unmap test. Debug v2/JIT runs with age 0, minimum one purge page
and the idle timer enabled pass all census assertions and pattern checks.

Cost check, same compiler/O3, round-6 baseline vs hardened v2, alternating
three runs of `bench/mt MODE 2000000 8`:

| mode | baseline median (range), s | hardened median (range), s |
|---|---|---|
| local | 0.061144 (0.053883–0.071806) | 0.075874 (0.048016–0.090201) |
| cross-free | 0.052916 (0.052026–0.059825) | 0.060605 (0.057068–0.068089) |

Cloud noise is obvious in the local range. Cross-free suggests a possible
~15% ownership cost; do not claim neutrality. **Accept the correctness fix**,
then re-measure downstream before deciding whether a more involved batch
reclamation design is worth its complexity.

## 3. Idle timer fork and signal safety (ADR 0036)

Fork handler registration now happens once with the existing thread-exit
initialization, before timer creation; a registration failure suppresses
the timer. Prepare waits for census and central ownership, so a timer
cannot leave its census's detached supply behind in the child snapshot.
Parent and child release the acquired locks. The parent keeps its timer;
the child disables its inherited timer state **until exec**. This intentionally
supersedes ADR 0032's child respawn: pthread_create is not async-signal-safe
in the multithreaded-fork child window.

The timer is detached at creation and inherits blocked application signals;
the creator's mask is restored on all paths. Sweep cadence now has a private
timestamp, so a slow sweep cannot overwrite a newer activity timestamp and
make the next idle decision early. No signal handler or application timer
is installed. Allocator/census entry points remain non-async-signal-safe;
fork from an allocator-interrupting signal handler and raw fork/_Fork/vfork
are outside this guarantee. Unloading the library while its worker runs
remains unsupported; this round does not implement a dlclose lifecycle.

`bench/idlefork.c` checks simultaneous starter bursts, exact signal-mask
restoration (including starters), process-directed SIGUSR1 delivery to the
caller, and four forks while four workers churn. The silent child and three
churning children all stay at one thread for 2.2 seconds; the parent ends
with exactly its original one timer. Repeated under v2/JIT with the timer on
and off. Absence of a child timer proves absence of a child sweep source.
The test has a 40-second deadlock alarm.

Parent behavior remains useful, measured by the existing idleprobe:

| mode | drain RSS KiB | idle 6 s RSS KiB |
|---|---|---|
| timer off | 39940 | 39944 |
| timer on | 40028 | 28340 |

With the timer on, the first drop is visible at 1.5 s and the final level
at 2.5 s. **Accept hardening; keep default off**. These are indicative cloud
RSS readings, not a comparison with round 6's VM readings.

`earlyinit.sh`: glibc, v1, v2, JIT all pass. `tlsexit.sh`: v2 RSS 1644 KiB,
JIT 1660 KiB, both pass their bound; glibc and v1 controls exit 0.
Separately, FM_DEBUG v2 and JIT stress pass with FM_RELEASE_AGE_MS=0,
FM_PURGE_MIN_PAGES=1, FM_IDLE_RELEASE=1. The final pointer-policy assertion
also passes all four realloccache combinations. `git diff --check` is clean.

Benchmark measurements above are **indicative only**. No reference-VM app
matrix, sanitizer proof, thread-creation fault injection or dlclose test is
claimed. Stress/assertions test exercised executions; the ownership audit
is what identifies the C races and motivates fixing them despite the old
build's passing stress runs.
