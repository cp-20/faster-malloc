
## Sanitizer proof

Scope: `d9c43642d708bc50ff88e4892b49ab050f4701ff` plus ADRs 0044–0046, on
branch `round9/sanitizers`. This section is independent of the parallel round-9
measurements. No allocation policy was changed.

### Compiler, flags and reproduction

Host: x86-64 Linux `6.18.57`, Debian glibc `2.41-12+deb13u4`.
Compiler: `/usr/bin/gcc`, `gcc (Debian 14.2.0-19) 14.2.0`.
All sanitizer runs use `-g -fno-omit-frame-pointer -fno-sanitize-recover=all`
and one of `-fsanitize=undefined`, `address`, `thread`, `address,undefined`,
`thread,undefined`. GCC rejects `address,thread` as incompatible; consequently
there is no three-sanitizer build. Runtime options: `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1`,
`ASAN_OPTIONS=halt_on_error=1`, `TSAN_OPTIONS=halt_on_error=1`.

The normal interposition matrix adds `-O2 -fPIC -fno-plt -Wall -Wextra
-Wno-unused-parameter -Isrc` to allocator builds; v2/JIT retain
`-shared -Wl,-z,nodelete`. Tests retain their exact Makefile/script flags
(usually `-O2 -g`, plus their existing `-pthread`/`-ldl` flags).
A compiler wrapper prepends the sanitizer flags to **every** compilation,
including scripts invoking literal `cc`, and lifecycle fault-injection DSOs.
`FM_DEBUG` adds `-DFM_DEBUG` to v2/JIT and runs stress against each.

Reproduce from the repository (run these sequentially; `run.py` rebuilds the
normal repository binaries):

```sh
python3 bench/sanitizers/run.py
python3 bench/sanitizers/namespaced.py
python3 bench/sanitizers/lifecycle.py
python3 bench/sanitizers/lifecycle.py --early-only
python3 bench/sanitizers/mt-recheck.py
python3 bench/sanitizers/probes.py
```

Logs and machine-readable per-case exit statuses/timings go to
`work/sanitizers/`, with the latter two suites in their own subdirectories.
The first runner executes `make`, the exact `bash bench/round7.sh`, then (if it fails) each
main battery case independently so an early failure cannot hide later cases.
It also invokes earlyinit, tlsexit and the full idlelifecycle script separately.

### Instrumentation boundaries

ASan and TSan replace malloc themselves. With our allocator first in
`LD_PRELOAD`, ASan exits 1 with “ASan runtime does not come first in initial
library list”; disabling `verify_asan_link_order` segfaults before `main`.
TSan with our allocator first also segfaults before `main`. These are startup
limitations, **not clean sanitizer runs or evidence of allocator races**.
A standalone malloc/free program works under each runtime on this host.
Preloading the runtime first makes that program run, but `dladdr` identifies
`libasan.so`/`libtsan.so` as the owner of malloc: that order bypasses our
allocator and is not accepted as proof. No suppression was used.

For useful internal instrumentation, the supplemental suites rename allocator
APIs and test calls to `fm_san_*` at compile time and link tests to the selected
v2/JIT DSO, leaving runtime allocations with the sanitizer. JIT's literal
assembly malloc export is renamed in a generated source copy too. Production
source/assembly dispatch is otherwise unchanged. Exact API names and commands
are in the runners. Supplemental flags are `-O2 -g -fno-omit-frame-pointer
-fno-sanitize-recover=all -fsanitize=...`, namespace defines, plus `-fPIC
-shared -Isrc -Wl,-z,nodelete -pthread` for DSOs and `-pthread -ldl` for tests.

The lifecycle supplement preserves all fault defines/expected values. It
renames the two dlsym lookup strings and removes `RTLD_DEEPBIND` in a generated
test copy because sanitizer interception forbids DEEPBIND. This is supplemental
coverage, not a claim that the original deep-binding load mode works with ASan.
The earlyinit dependency constructor is retained. Its stronger recheck preloads
the sanitizer runtime first and the namespaced allocator second: the loader
trace confirms the dependency constructor runs before the allocator constructor.
All eight earlyinit cases pass (32/32 build/run steps); these supersede the
initial simply-linked supplemental earlyinit cases. For TSan, the generated
idlefork/lifecycle parent thread-count expectations include one runtime helper
thread; child expectations remain one. A standalone pthread create/join control
reports `before=1`, `after_join=2` without our allocator.

TSan instruments allocator C code in all supplemental runs. The byte-intensive
test clients are compiled without TSan instrumentation and linked to its runtime;
this avoids the prohibitive cost of instrumenting every shadow-pattern byte
check (one fully instrumented v2 TSan stress run passed in 121.76 s; the remaining
full-client repetitions were stopped in favor of allocator instrumentation).
The actual stress workload/iterations and corruption checks are unchanged.
`mt` and the new `jitprofile` regression are fully instrumented: the former
requires visibility of its release/acquire handoff, and the latter tests the
profiling races. Lifecycle test clients are fully instrumented too. ASan and
ASan+UBSan instrument both allocator C code and all supplemental clients.
TSan+UBSan's uninstrumented byte-intensive clients likewise omit client UBSan
checks; allocator code has both sanitizers. No allocator JIT machine
code or hand-written assembly is instrumented by these C compiler sanitizers.
ASan does not automatically add per-object redzones/quarantine to mmap-backed
custom allocations, so a clean run cannot establish complete client buffer
bounds or use-after-free coverage. TSan sees instrumented C accesses and
synchronization, not accesses emitted by the JIT. Neither tool proves absence
of all memory bugs or races.

### Results and triage

The main supplemental matrix covers, **for each allocator**: basic under default
and all three profiles; stress ×3; check; mt local/cross-free; realloccache 0/1;
idlefork 0/1; both opt-ins on for basic and stress; and FM_DEBUG stress. JIT also
runs the 800,000-allocation, eight-thread profiling regression. The lifecycle
matrix covers earlyinit, tlsexit, normal lifecycle off/on, and all atfork/create/
retry fault cases including the two applicable idlefork fault cases.

| Sanitizer | Normal malloc interposition | Namespaced main cases, v2 / JIT | Namespaced lifecycle cases, v2 / JIT |
| --- | --- | --- | --- |
| UBSan | Exact round7 battery passes; FM_DEBUG stress passes for both | Covered by normal battery | Covered by normal battery |
| ASan | Startup/load-order and DEEPBIND limitations | 17/17 / 18/18 pass | 9/9 / 9/9 pass |
| TSan | Startup and DEEPBIND limitations | 17/17 / 18/18 pass after instrumenting mt handoff | 9/9 / 9/9 pass |
| ASan+UBSan | Same ASan limitations | 17/17 / 18/18 pass | 9/9 / 9/9 pass |
| TSan+UBSan | Same TSan limitations | 17/17 / 18/18 pass after instrumenting mt handoff | 9/9 / 9/9 pass |
| ASan+TSan (including triple) | GCC rejects combination | Not feasible | Not feasible |

The exact UBSan `bash bench/round7.sh` run exited 0 in **221.54 s**; its two
FM_DEBUG stress runs also exited 0. Timings reflect a shared host and concurrent
independent suites, and are not allocator performance measurements.
All five sanitizer configurations built successfully with make; startup failures
are retained as failures, not counted as passing correctness tests.

ADR [0044](adr/0044-posix-memalign-error-output.md) fixes a confirmed API bug:
invalid alignment cleared the caller's posix_memalign output, and zero
alignment was not rejected. Namespaced ASan basic failed 4/4 v2 profile cases
before the change; the strengthened regression checks alignments 0, 3 and 24
through a volatile function pointer. The ordinary direct call allowed GCC's
builtin assumptions to conceal the store. This was a correctness-test report,
not an ASan shadow-memory diagnostic. No speculative allocator fixes were made.


The other confirmed reports are documented in ADR
[0045](adr/0045-jit-profile-races.md) (non-atomic JIT trigger and give-up flag)
and [0046](adr/0046-idle-fault-counter.md) (test-only failure-injection counter).
The JIT reproduction initially reported three TSan warnings across the two
variables; the fixed, fully instrumented 800,000-allocation regression exits 0
under TSan and TSan+UBSan and logs the broad-distribution fallback.

The four initial TSan cross-free reports were **instrumentation false positives**:
compiling `bench/mt.c` without TSan hid its release/acquire ring publication,
so TSan could not see the happens-before edge from span initialization to free.
Fully instrumenting that small client removed the reports: local and cross-free
both pass three repetitions for each allocator under TSan and TSan+UBSan
(**24/24 runs**, no suppression and no allocator change). The retained initial
namespaced results include those exit-66 reports; the mt-recheck results
supersede them. Initial thread-count assertions likewise reflect the verified
runtime helper thread, and are corrected only in generated sanitizer test copies.
Compiler alloc-size overflow warnings in test_basic are intentional negative
API tests, not sanitizer reports.


Final lifecycle recheck: **144/144 build/run steps passed**, including all
72 runtime cases, after ADR 0046. The subsequent constructor-order-verified
earlyinit recheck also passes all eight runtime cases (32/32 build/run steps). The original failing retry report is retained.
The final uninstrumented `make` plus `bash bench/round7.sh` battery also exits 0.
No untriaged sanitizer reports remain in the completed coverage described above.
ADRs 0044–0046 are used; ADRs 0041–0043 were left untouched.

Retained evidence: [case results and transcripts](sanitizers-round9/README.md),
including the exact compiler version, original startup failures, initial race
reports, subsequent clean runs, and the normal battery output. Raw main results
retain the four cross-free false positives; the separate fully instrumented mt
recheck supersedes them. The direct interposition failures and forbidden
combinations remain documented tool limitations, not sanitizer passes. The
namespace and instrumentation boundaries above are part of the result.
